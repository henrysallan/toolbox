# Assets (spec, 2026-06-29)

A project-associated **Assets** concept: bundled custom fonts, plus an
external `assets/` folder of media, surfaced in two places (the Project view
and the parameter panel) and draggable into the node editor. Companion to
[062926_compositions-and-project-view.md](062926_compositions-and-project-view.md).
Read the asset/serialization bottom of
[061226_devguide.md](061226_devguide.md) ("Persistence & sharing") first.

## Goal (the four asks)

1. **Comps / Assets toggle** in the Project view — a pill switching the panel
   between the compositions grid/table and a new **Assets** view.
2. **Bundle custom fonts** (not videos) into saves, and list them in Assets.
3. **Scan the opened `.toolbox`'s directory for an `assets/` folder** and show
   its contents in the Assets view.
4. **File → Assets** opens the Assets view in the **parameter panel** (not the
   Project view), so assets can be **dragged into the node editor**.

## Decisions (locked with owner, 2026-06-29)

- **Folder scan = both platforms.** Desktop **auto-scans** the folder next to
  the opened `.toolbox`. Web can't auto-scan (no path), so it offers a **"choose
  assets folder"** button via the File System Access API (Chromium). Folder
  assets are **referenced, read on demand — never bundled**.
- **Fonts bundle into both cloud + `.toolbox`** (small; preserves type
  everywhere; fixes today's silent fallback-to-enum on reload).
- **Drag → node:** media (image / svg / video / audio) create their Source
  node (reusing `onAddFileNode`); a **font** creates a **Text node** preset to
  that font.

## Two kinds of asset

| | Bundled | Folder |
|---|---|---|
| **What** | custom fonts (today); the existing image/paint node-params already bundle | files in an external `assets/` folder (image/video/audio/svg/font…) |
| **Stored** | in the save (cloud row + `.toolbox` `assets/`) | **not** stored — referenced by path (desktop) / handle (web), read on demand |
| **Source** | derived from the graph (Text nodes' custom fonts) | the sibling folder (desktop) or a user-picked folder (web) |
| **Offline** | always available | desktop: always (local FS); web: while the handle is granted |

The Assets view shows both as **sections**: **In project** (bundled) and
**Folder** (external, with the folder name / a "choose folder" button on web).

## Font bundling (the serialization change)

Today `serializeParams` ([project.ts](../src/lib/project.ts)) nulls `font`
params ("FontFace refs don't survive a reload"). The bytes *do* exist at upload
(`registerCustomFont` in [fonts.ts](../src/lib/fonts.ts) reads
`file.arrayBuffer()`) but aren't retained. Plan:

1. **Retain the buffer.** `registerCustomFont` stashes the `ArrayBuffer` in a
   module-level `Map<family, ArrayBuffer>` (engine stays self-contained — this is
   lib-side). Keyed by the synthetic `family` it already mints.
2. **Serialize** the `font` param as a `{ kind: "font", dataUrl }` envelope
   (base64 of the buffer) instead of `null`. The `.toolbox` writer already
   extracts any `dataUrl` param into a deduped `assets/<hash>` binary
   ([project-file.ts](../src/lib/project-file.ts) `isInlineAsset`) — fonts ride
   that path for free; cloud inlines the base64.
3. **Deserialize** rebuilds a `FontFace` from the buffer, re-registers it (so the
   same synthetic `family` resolves), and restores the `FontParamValue`
   (`family`, `filename`, parsed `axes` via [font-parse.ts](../src/lib/font-parse.ts)).
4. **Back-compat:** pre-v? saves have `font: null` → unchanged fallback to the
   `font_family` enum. No schema bump needed (additive envelope, like the other
   media envelopes).

The **Assets "In project"** section enumerates custom fonts by scanning Text
nodes' `font` params (deduped by `family`), reading metadata from the buffer Map.

## Folder assets (platform work)

The bridge ([src/lib/platform](../src/lib/platform)) gains, behind capability
flags (callers gate on presence — same pattern as `encodeVideo?`):

- **Opened-file path (desktop).** Today `pickOpenFiles` / `recents.open` return
  only `{ name, bytes }`. Add the **full path** to the toolbox-open result so the
  renderer can derive the parent dir. (electron/files.js already has it at the
  dialog; recents.js already stores it.)
- **`listDirectory(path)` (desktop).** New ipc handler → `fs.readdir` of
  `<dir>/assets`, returning `{ name, size, ext }[]` (no bytes).
- **`readFileAt(path)` (desktop).** New ipc handler → `fs.readFile`, returning
  bytes — used lazily for thumbnails and on drag-to-create. Main validates the
  path is under a known-opened directory (same trust model as recents).
- **Web `pickAssetsFolder()`** → `showDirectoryPicker()` returns a
  `FileSystemDirectoryHandle`; list via the handle, read entries on demand.
  Persist nothing (handle is session-scoped; re-pick per session).

`platform.isNative` picks auto-scan vs. the web folder-picker. On `.toolbox`
open (desktop), derive `dir`, look for `dir/assets`, list it → folder assets.

## UI surfaces (one shared view, two mounts)

A single **`AssetsView`** component, fed an `assets` list + handlers, mounted in
two places:

- **Project view** (M-A1): a **Comps / Assets** pill at the top of
  [ProjectView](../src/components/effects/ProjectView.tsx) toggles the body
  between the compositions grid/table and `AssetsView`.
- **Parameter panel** (M-A1): **File → Assets** sets a new
  `paramView: "assets"` ([EffectsApp](../src/components/effects/EffectsApp.tsx),
  [ParamPanel](../src/components/effects/ParamPanel.tsx)) rendering `AssetsView`
  in the right-hand panel — the mount you drag *from* into the node editor.

`AssetsView` renders the two sections (In project / Folder), each item a card
(thumbnail for images, type glyph otherwise) with name + kind. Reuses the
ProjectView icon/spacing conventions.

## Drag → node editor

- Asset cards set `dataTransfer.setData("application/x-toolbox-asset",
  JSON.stringify({ source, kind, ref }))` on drag start (`source`: bundled |
  folder; `ref`: family for fonts, path/handle-id for folder files).
- `NodeEditor.onDrop` already handles OS file drops → `onAddFileNode`; add a
  branch for the asset datatype: resolve bytes (folder → `readFileAt` / handle
  `getFile()`; bundled font → the buffer Map), then:
  - image/svg/video/audio → the existing `onAddFileNode` path (Source node, root
    auto-wrap into a Layer as today).
  - **font → a Text node** with the font param preset to that family.

## Invariants & back-compat

- **Engine self-containment** (#1): the font buffer Map + asset logic live
  lib/component-side; `src/engine` + `src/nodes` stay agnostic.
- **No schema bump** for fonts (additive media envelope); ≤ current saves with
  `font: null` keep loading.
- Folder assets are **never serialized** (referenced) — a save records nothing
  about the external folder; re-derived on open.
- Native FS methods are **optional** on the platform interface; web/headless gate
  on presence and degrade to bundled-only + the folder-picker.
