"3D cameras/lights/nulls and GLB passthrough"). Branch
`claude/ae-m4-3d-c89419`. Measured 2026-10-21 in After Effects **26.5

## Feasibility: yes

A headless build imports a `.glb` **and** an `.obj` as 3D model layers,
renders them with the Advanced 3D renderer and saves the project, with two
caveats that the builder now handles:

- **OCIO projects refuse 16 bpc.** AE's sticky "Last Project Settings" pref
  changed on this Mac on 2026-10-21 (14:26) to `colorManagementSystem: 1`
  (OCIO, Blender's `config.ocio`). aerender's startup project inherits it, and
  then `app.project.bitsPerChannel = 16` throws "Not supported for OCIO color
  managed mode". `app.project.colorManagementSystem = 0` (Adobe) fixes it.
  26.5 has no enum object for this, so the value is a plain number. build.jsx
  switches the project before setting the bit depth. The pref itself was not
  changed. **This affects every lane's live builds**, not only 3-D.
- **A save race on model imports.** Saving right after importing models can
  store a broken model item. Its comp renders fully transparent, and every
  re-render of the saved `.aep` gives the same result. Without a pause, 7 of
  12 conclusive unsettled builds lost one or more model comps (usually the
  last-imported ones). With a pause of 1 s or more, 8 of 8 kept every model. build.jsx sleeps `min(5 s, 1 s + 0.5 s ×
  models)` before saving when it imported a model. No ExtendScript property
  showed the difference, so no signal is available to wait on.

| question | measured |
|---|---|
| import | `app.project.importFile(new ImportOptions(file))` → a `FootageItem` (GLB 0.37 s first, ~0.005 s after; OBJ 0.11 s), nominal 1920×1080, 30 s |
| layer | `comp.layers.add(item)` → `ThreeDModelLayer`, match name `ADBE 3D Model Layer`, `threeDLayer` true |
| renderer | new comps already default to `ADBE Advanced 3d`. `comp.renderers` = Advanced 3d, `ADBE Calder` (Classic 3D), `ADBE Ernst` (Cinema 4D) |
| render | aerender renders it (TIFF / 16-bit PNG). Classic 3D still draws a model (the model forces Advanced 3D) |
| OBJ | same path, the same 512 px per unit. With no MTL, AE's default material shows (0.64 vs the GLB's 0.69 under one light) |
| light types | `LightType.PARALLEL / SPOT / POINT / AMBIENT / ENVIRONMENT` all exist |

## Coordinates (exact)

Measured with `calibrate/three-d.mts` steps `units`, `units2` and `math`:

| fact | measured |
|---|---|
| model units | **512 px per glTF unit** (a unit cube's front face 525.37 px through a 10⁴-zoom camera ⇒ 511.92). The same for cubes of 0.1, 1 and 10 units at 1000 / 100 / 10 % scale, and for 400² and 1000² comps. `sourceRectAtTime` reads −256 / −588.8 / 844.8 for the axes model, i.e. exactly 512 |
| axes | glTF `(x, y, z)` → AE `(x, −y, −z)`; +Y draws up, +Z toward a default camera. The file's origin sits at the layer anchor, with no re-centring |
| rotation | AE's layer rotation matrix is **Rx·Ry·Rz**, read back exactly through `toWorld()` expressions on 3D Point Controls. That is three's 'XYZ' Euler. `Orientation [30,40,50]` ≡ X/Y/Z Rotation 30/40/50. F = diag(1,−1,−1) is a rotation, so X = a, Y = −b, Z = −c, per axis |
| camera basis | a Point-of-Interest camera has right = down × forward with right horizontal: three's `lookAt` under F (identical bases, roll-free). Z Rotation rolls about the forward axis |
| parenting | `toWorld` through a parent equals T·R·S composition, with anchor 0 on both |

Model layer: Position = O + 512·(x, −y, −z) with O = comp centre (or 512·…
in a Transform 3D null's space), Scale = 100·s, X/Y/Z Rotation =
rot_x / −rot_y / −rot_z, anchor 0.

## Camera

- Zoom = (H/2)/tan(fov/2), POI = target, Position = camera position.
- Sphere silhouette vs toolbox's render of the same graph (`lights` step):
  **IoU 0.9989, centroid ≤ 0.056 px, width 304.63 vs 304.50 px**.
- **Orthographic → approximation, not bake.** AE has no orthographic camera.
  The stand-in is a camera D px from the target along toolbox's view
  direction, zoom = D·H/(512·ortho_height). Measured with a directional light
  (`ortho` step, `LIT=1`):

  | D (px) | silhouette IoU | centroid Δ (px) | notes |
  |---|---|---|---|
  | 2·10⁴ | 0.983 | 0.25 | perspective shows |
  | 5·10⁴ | 0.993 | 0.10 | |
  | 10⁵ | 0.996 | 0.05 | |
  | **2·10⁵** | **0.997** | **0.055** | chosen: clean edges |
  | 5·10⁵ | 0.997 | 0.06 | first edge fringes (p99 colour 0.19) |
  | 10⁶ | 0.997 | 0.05 | depth-precision fringes on every edge under directional light (an ambient-only test hid them) |

  At 2·10⁵ a point 1.65 units in front of or behind the target moves ≤ 0.9 px.
  Deeper scenes drift more.
- Depth of field bakes. three's BokehPass aperture / maxblur have no
  calibrated AE camera DOF. Near / far are not clipped in AE (reported when
  they would clip).

## Lights (approx)

- **The Advanced 3D renderer shades in the encoded working space.** With the
  project's working space unlinearized (the project keeps Linearize Working
  Space off), a GLB albedo of 0.6 (linear) shows as 0.7961 under a 100 %
  ambient light. That is the sRGB-encoded 0.6, so AE converts the material to
  display values and then multiplies. Under a Parallel light the output falls
  off as N·L on the encoded value: out = encode(albedo) × I/100 × N·L. three
  lights in linear and then encodes: encode(albedo × I/π × N·L).
- No intensity matches every N·L. AE is linear in N·L and toolbox is ≈
  (N·L)^(1/2.4). The mapping takes the least-squares scale over a lit sphere
  (N·L weighted by projected area, 2x dx): **AE % = 100 · 1.16 ·
  encode(I/π)**. 1.16 = 4∫₀¹x²·encode(x)dx, which ranges 1.145–1.163 for I/π
  from 0.1 to 1.5. On the round trip's frames the best per-frame scale was
  1.09–1.21. Ambient has no N·L term, so it is matched exactly:
  100 · encode(I/π).
- Point / spot: AE **Inverse Square Clamped** with **Radius 512 px** gives
  I·(r/d)², three's decay-2 falloff in world units (`point_isq`: AE 0.7961 at
  d = 2 for 318 % = 3.18/4 ✓). The intensity is matched at the distance to
  the camera's target at frame 0. Because AE falls off in encoded space, the
  falloff is steeper than toolbox's.
- Spot: **Cone Angle = 2·angle** (three's `angle` is the half-angle) and
  **Feather = 100·penumbra**. The profiles agree in shape (`spot`,
  `spot_soft`).
- Color: the hex goes through as 0–1 encoded RGB.
- AE hides options a light type does not use, and refuses values on them. A
  Parallel or Point light has no Rotation, Point has no Point of Interest,
  Ambient has no transform and no Casts Shadows, and Radius / Falloff
  Distance need their falloff set first. build.jsx sets the type at creation
  and skips what the type hides. The validator refuses cones on non-spots and
  shadows on ambient.
- No light wired → the 0.4 ambient light Scene Render adds.
- The `lights` step's per-case numbers in `three-d-lights.json` came from the
  first-guess mapping (AE % = 100·I/π, linear). They are the data that
  identified the encoded-space model, not the shipped mapping's error. The
  shipped mapping's error is the round trip below.

## Round trip (GLB + camera + lights)

and `t-scene3d-ortho` fixtures into packages with the real build.jsx in
aerender's core (run.mts `--fixtures`: 48 checks pass, build problems 0). It
renders the queued frames and compares them with the same graphs rendered by

`calibrate/measured/three-d-roundtrip.json`.

`t-scene3d` is the axes GLB under a Transform 3D with a keyed eased Y
rotation, a camera with keyed X / Z on different timing, plus directional,
point and ambient lights. `t-scene3d-ortho` has an orthographic camera, a
spot light and a solid background.

| t-scene3d @ 0 | 0.998 | −0.055, −0.001 | identical | 1.000 | 0.090 / 0.118 / 0.170 |

**Camera framing matches to well within a pixel.** The lighting error is
recorded above: values are 0–1, so mean 0.04–0.09 is 10–23 / 255. Before the
1.16 gain the means were 0.137 / 0.063 / 0.052. AE is darker toward the
terminator and hotter where light hits a face head-on. The ortho max is the

- Build: 1.8–1.9 s per package, including the settle.

## What exports natively

A Scene Render qualifies (`src/lib/ae-export/three-plan.ts`) when:
- every object is a Light or an Import 3D (GLB / glTF / OBJ, `object` = "")
  under zero or more Transform 3D nodes;
- the camera is a Camera node without DOF, or none;
- fog and environment are `none`.

It becomes:

| toolbox | AE | fidelity |
|---|---|---|
| scene-render | 3-D precomp, renderer `advanced-3d`, placed as one 2-D precomp layer (`ctx.free`, so a toolbox layer's TRS lands on it) | exact container |
| import-3d | model footage (`AeFootage.kind` `model`, `footage/<id>.glb`) + a 3-D footage layer; `AeAssetCopy` kind `model` | approx (materials) |
| transform-3d | a 3-D null the model / next null is parented to | exact (shear note when a rotation sits over a non-uniform scale) |
| camera-3d | camera layer (`AeLayer.camera.zoom`; POI = `transform.anchor`) | exact; ortho approx |
| light-3d | light layer (`AeLayer.light`) | approx |
| background solid | 2-D solid at the bottom (a rectangle shape when keyed) | exact |

Keys:
- Position axes with their own timing go to separated X / Y / Z, keyed per
  axis through `convert/` with eases kept.
- A target becomes one spatial Point of Interest, sampled when its axes key
  apart.
- Scale is one ThreeD property, combined.
- Rotations are per axis.
- FOV and intensity keys are sampled per frame, because their maps are not
  affine.
- Wired (driven) params are sampled, as elsewhere in the walk.

Everything else bakes the whole Scene Render, with a reason in the report:
- fog;
- environment `room`;
- DOF;
- primitives, materials and modeling nodes (`cube-3d (box) feeds scene2…`);
- STL;
- a picked file object (`top:<i>`): AE imports the whole file as one layer;
- a non-Camera camera source.
